# Решения и открытые вопросы

Обновлено: 2026-10-08. Различать цель пользователя, инженерное правило и предложение. Новую запись снабжать датой, основанием и последствиями; заменённую помечать superseded.

## Подтверждённые цели

### D-001 — Магистерская диссертация и рабочий инструмент

Подтверждено пользователем 2026-09-30. Реализация должна быть связана с научной задачей приложенного обзора и экспериментами, а не ограничиваться demo/CI.

### D-002 — Контекст хранится в репозитории

Подтверждено текущим запросом 2026-09-30. Пользователь планирует активно использовать AI-ассистента. Инженерная реализация: AGENTS, устойчивый контекст, текущее состояние, решения, шаблон эксперимента. Документы поддерживаются компактными и актуальными.

### D-005 — Основной предмет исследования: truth/lie

Принято пользователем 2026-09-30. Основной эксперимент классифицирует правдивость высказываний (truth/lie) по данным айтрекинга. CIT не заменяет этот target; его метки и результаты остаются отдельными. Проведение дополнительного CIT-эксперимента не утверждено. Основание: прямой выбор пользователя при фиксации исследовательской задачи. Последствия: нужны записи высказываний с проверяемой разметкой truth/lie; источник данных, протокол, единица разметки и итогового решения пока не выбраны. Связанные документы: PROJECT_CONTEXT, WORK_STATUS, THESIS_IMPLEMENTATION_PLAN_RU.

### D-006 — Сейчас искать открытые данные без участия руководителя

Принято пользователем 2026-09-30: руководитель временно недоступен; пользователь сообщит, когда доступ появится. Продолжить поиск открытых вариантов. Bag-of-Lies остаётся кандидатом, запрос с институциональной подписью отложен. Это не смена основного truth/lie target и не принятие CIT или табличной карточной игры в качестве основного эксперимента. Связанные документы: DATASET_SEARCH_RU, WORK_STATUS.

## Инженерные основания

### D-003 — Техническая работоспособность и научное качество различаются

Инженерное правило на основе темы и аудита, 2026-09-30. Synthetic accuracy, тесты и быстрый forward pass не доказывают live deception detection. Качество, причинность, время накопления, задержка и устойчивость проверяются отдельно.

### D-004 — Существующая архитектура остаётся основой

Инженерный выбор подготовки, 2026-09-30. Сохраняются src/YAML/pytest/pyproject; инструменты добавляются по реальной потребности. Этот запрос не выбирает UI/framework, БД или облако.

### D-007 — Агентный слой вокруг существующего pipeline

Принято по отдельному поручению пользователя 2026-10-06, вне основного плана.
Добавлены шесть специализированных агентов и детерминированный Orchestrator
в существующий Python monolith, с CLI вместо отсутствующего backend, без новых
зависимостей/LLM. Инженерный выбор: dataclasses с валидацией, tools/services вокруг
существующих адаптеров, preprocessing, extractor и saved baseline/LSTM/TCN.
Inference не получает labels; target/classes/units/preprocessing декларируются
явным ModelSpec с SHA256. Configurable quality/verification defaults обозначены
инженерными и не являются научными порогами. Default confidence policy не задана,
поэтому verification INCONCLUSIVE. Файловый источник не повторяется ради того же
плохого сигнала; retries доступны refreshable/transient acquisition и ограничены.
Это не завершение STREAM-01, PIPE-01 или полного MODEL-01 и не выбор устройства/UI.
Основание и описание: [MULTI_AGENT_ARCHITECTURE_RU.md](MULTI_AGENT_ARCHITECTURE_RU.md).

### D-008 — Наглядный показ через автономный HTML

Инженерный выбор по запросу пользователя о запуске и демонстрации, 2026-10-06.
Существующий synthetic пример реально выполняет три workflow и формирует
portable HTML без backend/server и новых runtime-зависимостей. Viewer показывает
сохранённые reports/events, не вызывает модель и не подаёт поток samples;
анимация явно обозначена как объяснение журнала, не physical live/replay.
Однокнопочный Windows launcher использует проектную `.venv`. Готовый HTML
можно передать отдельным файлом. Это демонстрационный viewer, не принятие
полноценного UI/устройства из основного плана. Инструкция: [DEMO_GUIDE_RU.md](DEMO_GUIDE_RU.md).

### D-009 — Строгий offline analysis для Assignment 3

Инженерное решение по отдельному заданию пользователя 2026-10-08, вне основного
плана. Новая небольшая область `src/eye_tracking_analysis/` использует существующие
NumPy/pandas/Matplotlib, но не вызывает permissive legacy preprocessing:
обязательные participant/session/trial, явные единицы, строгие timestamps,
ограниченная offline interpolation, time-window mean и фиксированная геометрия
screen normalization. Velocity events — инженерные оценки с явными порогами;
blink только из наблюдений, отсутствующие temporal measurements не подставляются.
Labels не используются. Оригинальные модели/обучение не изменены. Новых runtime
dependencies нет. CI запускает новый synthetic пример; deep — manual/tag,
release требует отдельного `ENABLE_RELEASE=true`. Никаких remote settings/push
или публикации не выполнено. Это не принятие научного threshold/метрики,
не causal/live readiness и не закрытие PIPE-01/DATA-03. Основание и контракт:
[Assignment 3](assignment_3/GUIDE_RU.md).
